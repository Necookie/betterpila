# Product Roadmap

**Status:** Proposed  
**Last updated:** 2026-09-13

The roadmap is organized by verified outcomes rather than fixed dates. A phase completes only when its exit criteria are met.

## Phase 0 — Foundation

- Confirm project ownership and at least one local reviewer.
- Register Better Pila as planned in the BetterGov directory.
- Approve the PRD, SRS, architecture, and editorial policy.
- Create shared GitHub and Cloudflare access with recovery arrangements.
- Initialize Astro, TypeScript, Tailwind, Worker, D1, R2, and test tooling.
- Establish preview and production environments.

**Exit:** Two maintainers can work safely, automated checks pass, and a preview deployment is available.

## Phase 1 — Publishing core

- Implement identity verification and local roles.
- Implement sources, citations, documents, revisions, and workflow states.
- Build the dashboard shell and review queue.
- Build public layout, disclaimer, methodology, and base SEO components.
- Establish export, backup, and restore procedures.

**Exit:** A synthetic record can move from draft through review to a public page with a citation and revision history.

## Phase 2 — Officials and contacts

- Implement officials, offices, contact methods, and official channels.
- Add search and filters.
- Collect and review the initial Pila records.
- Complete accessibility and mobile review for these workflows.

**Exit:** Verified officials and primary municipal contacts are ready for public use.

## Phase 3 — Documents and ordinances

- Implement safe upload, quarantine, review, and download.
- Implement ordinances and resolutions.
- Add HTML summaries and document accessibility metadata.
- Add permanent redirects and sitemap coverage.

**Exit:** Recent verified legislative documents are discoverable by year and number.

## Phase 4 — Budgets and projects

- Implement budget records and optional line items.
- Implement projects and status-event history.
- Add relationships among budgets, projects, offices, sources, and documents.
- Add carefully labeled summaries and calculations.

**Exit:** Initial sourced budget and project information passes editorial and domain review.

## Phase 5 — Launch readiness

- Complete representative content coverage.
- Conduct security, accessibility, performance, SEO, and privacy reviews.
- Rehearse backup restoration and incident response.
- Configure production domain, webmaster tools, analytics, and monitoring.
- Invite local residents to review the preview.
- Resolve critical feedback and publish launch communications.

**Exit:** Every release criterion in the PRD and test plan is satisfied.

## After launch

- Quarterly content review sessions.
- Correction tracking and public changelog.
- Improved bilingual support.
- Data exports and carefully scoped public API.
- Better project and budget visualizations.
- Protected public feedback intake.
- Shared components that may later support Better Victoria.

These items require demonstrated need and maintenance capacity; they are not assumed commitments.
